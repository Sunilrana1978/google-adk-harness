Harness Demo, Explained

One generic ADK orchestrator. New business workflows are Markdown files, not new Python.

The big idea. Build the hard infrastructure once (context management, sandboxing, delegation, tracing, identity). Domain experts add workflows by writing SKILL.md files. At runtime the orchestrator reads a short skill index, picks skills, and spins up an isolated sub-agent per skill, each with its own model and tools.

1. How a request flows

Example: "Can order C300 be refunded, and which region grew faster Aug to Oct?"

Orchestrator (fast Flash model) sees only the skill index: one line per skill. Greetings and "what can you do?" are answered right here, with no delegation.
▼ two independent parts: one turn, two calls
delegate_task("refund-policy", task, summary₁)
Default model. Only lookup_order and check_refund_eligibility. Fresh session.
delegate_task("sales-analysis", task, summary₂)
Pro model. Only run_sales_query and run_python (sandboxed). Fresh session.
▲ run concurrently; only the final answers return
Orchestrator merges the two answers. A part with a non-ok status is reported as failed, not guessed.

4. The key pieces

A skill is Markdown, with an optional model skills/sales-analysis/SKILL.md

---
name: sales-analysis
description: Analyze sales numbers by region or product.
tools: run_sales_query, run_python
model: gemini-2.5-pro
---
1. Call `run_sales_query` ...
2. If a calculation is needed, call `run_python` ...
  • No model: means the default. A model not on the allowlist in config.py fails loudly.
  • Unknown tool, misspelled key, or a name that does not match its folder raises an error at load. Startup fails fast; at runtime only that skill is hidden.
  • Files are parsed once and re-parsed when their mtime or size changes.
  • Skill files are a security surface: they set instructions, tools and model. Keep them in version control with required review.

Delegation app/delegate.py

skill = get_skill(skill_name)                       # validated, cached
tools = [TOOL_REGISTRY[t] for t in skill.tools]     # least privilege
sub_agent = Agent(model=skill.model,                # model per skill
                  instruction=skill.body + summary, # callable: no {var} templating
                  tools=tools, before_tool_callback=guard)
# fresh session; run under a timeout; return only the final text
# span: skill, model, tools, status, duration_ms, setup_ms, run_ms

Context summary from parent to child

The orchestrator writes a new one to three sentence summary for each call: the user's goal, what is already established, and why this skill is being called, with nothing sensitive the skill does not need. It is capped at 600 characters (longer is truncated and the orchestrator is told) and lands in the sub-agent's instruction, labelled as background rather than instructions.

Parallel delegation

ADK runs each tool call of one model turn as its own asyncio task. delegate_task is async and shares no mutable state, so independent parts overlap. Gotcha: ADK runs sync tools on the event loop, so a blocking sync tool would freeze all delegations. The sandbox and run_python are async for that reason; real I/O tools should be async def.

Tracing app/telemetry.py

  • Turn on export: adk web --otel_to_cloud (Cloud Trace and Cloud Logging).
  • Sub-agent spans nest under the orchestrator's execute_tool delegate_task span because delegation runs in the same process and async flow. A test checks this instead of assuming it.
  • The parent session id is stamped as harness.correlation_id on every span during a delegation, plus the sub-agent's session state, session id and logs. One filter shows the whole flow.
  • harness.setup_ms is the harness's own overhead; harness.run_ms is the sub-agent's model and tool time.

5. Evals with agents-cli

  • tests/eval/datasets/skill-selection-dataset.json: 8 cases. One per skill, two multi-intent, one "status only" case that must not trigger refunds, and two that must not delegate at all.
  • skill_selection metric: deterministic, no judge model. Score 1 only if the delegated skills equal the expected set, so a missing skill, an extra skill, or any delegation for a trivial question scores 0. It fails closed on unknown prompts or unreadable traces.
  • Run: agents-cli eval run --dataset tests/eval/datasets/skill-selection-dataset.json --config tests/eval/eval_config.yaml

6. Identity and credentials

Prefer Agent Identity on Agent Runtime, Gemini Enterprise and Cloud Run: a per-agent SPIFFE-based identity, short-lived certificate-bound tokens, no long-lived keys. Real tools use Application Default Credentials.
Gotcha: redeploying creates a new principal, so re-run deploy/iam.sh after every deploy. Deleting an agent leaves its bindings behind (./deploy/iam.sh remove).

8. Honest limits

  • Verified here: the harness runs end to end against scripted models (real ADK runner, sessions, tool dispatch and spans), ADK's own loader discovers the app, and the tests fail when the code is deliberately broken (serialized delegation, no correlation stamping, ignored model, detached span context).
  • Not verified here: behaviour with a live Gemini model (does it pick the right skills, write good summaries, emit parallel calls), how Cloud Trace renders the spans, agents-cli eval run itself, and deploy/iam.sh against a real project.
  • Model names are placeholders; edit the allowlist in config.py.
  • Each delegation adds model round trips (a few seconds). Measure with the trace attributes before optimizing.
  • The sandbox cannot block the network; use an egress allowlist or a managed executor in production.
  • Reusing ADK's running compaction summary instead of a per-call summary (optional in the plan) is not implemented.
